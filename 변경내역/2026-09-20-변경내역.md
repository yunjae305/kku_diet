# Codex · 2026-09-20 · 쿠팡 랜덤 상품 직접 연결

**주요 파일**: `app.py`, `README.md`

**관련 커밋**: `36f1fd7` (직접 연결 기능, `origin/master` 푸시 완료)

## 배경

사용자는 커스텀 메뉴를 한 번 눌러 DB의 랜덤 쿠팡 상품으로 이동하기를 요청했다.
기존 `/api/recommend`는 POST 요청으로 상품 카드를 반환하므로 브라우저의 URL 연결에 사용할 수 없었다.
새 주소를 안내한 시점의 운영 서버에는 해당 경로가 없어 404가 발생했다.

## 상세 변경

- 메뉴 URL: `https://kku-diet.onrender.com/go/coupang`.
- 선택한 상품의 저장된 파트너스 링크와 쿼리 문자열을 유지한다.
- 같은 상품이 연속 선택될 수 있다.
- 작업 전부터 있던 `RECOMMEND_INTRO` 관련 미커밋 변경은 보존하고 이번 직접 연결 변경과 구분한다.

## 영향 및 호환성

- DB 스키마, 저장된 상품 데이터, 환경변수, 인증 설정 변경 없음.
- 기존 `POST /api/recommend` 응답 계약 유지. 공개 GET 경로 하나 추가.
- 서버에 배포한 후 카카오 메뉴 연결을 URL 방식으로 설정해야 한다.
- 직접 이동은 기존 카드의 수수료 안내를 표시하지 않으므로 클릭 전 안내 위치는 별도 설정이 필요하다.

## 확인

- Flask 테스트 클라이언트와 모의 상품 조회로 서로 다른 두 요청의 302 응답, 파트너스 URL 및 쿼리 보존, `no-store` 확인.
- 상품 없음·잘못된 링크 9가지와 DB 예외의 503 안내 응답 확인.
- 기존 상품 카드, 파트너스 안내, 기존 로컬 도입 문구 설정 및 `/health` 응답 유지 확인.
- 첫 검증에서는 PowerShell 표준입력의 한글 인코딩으로 테스트 문자열 비교가 실패하여 Unicode 이스케이프로 고친 뒤 모두 통과했다.
- 배포 전 운영 주소 GET 요청: 404 확인.
- `36f1fd7` 푸시 후 운영 주소가 302로 전환되는 것을 확인했다. 운영 DB에서 선택한 `link.coupang.com` 링크와 `Cache-Control: no-store` 응답을 확인했다.
- 추가 운영 요청의 이동 대상이 로컬 `ads.json`에 등록된 파트너스 링크와 일치하는 것을 확인했다. 쿠팡 외부 페이지까지 따라가지는 않았다.
- Render 관리 화면은 연결된 브라우저가 없어 확인하지 못했으며, 실제 운영 서버 응답으로 반영 여부를 검증했다.
- `git diff --check` 통과.
