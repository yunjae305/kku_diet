# Codex · 2026-09-20 · 쿠팡 랜덤 상품 직접 연결

**주요 파일**: `app.py`, `README.md`

**관련 커밋**: `36f1fd7` (직접 연결 기능, `origin/master` 푸시 완료)

## 배경

사용자는 커스텀 메뉴를 한 번 눌러 DB의 랜덤 쿠팡 상품으로 이동하기를 요청했다.
기존 `/api/recommend`는 POST 요청으로 상품 카드를 반환하므로 브라우저의 URL 연결에 사용할 수 없었다.
새 주소를 안내한 시점의 운영 서버에는 해당 경로가 없어 404가 발생했다.

## 기존 → 변경 후

| 구분 | 기존 | 변경 후 | 변경 이유 |
|---|---|---|---|
| 직접 연결 | 메뉴에서 상품 카드를 호출한 후 쿠팡 버튼을 다시 눌러야 했다. | `GET /go/coupang`에서 기존 `get_random_ad()`로 활성 상품을 고르고 저장된 파트너스 링크로 302 이동한다. | DB의 랜덤 선택을 유지하며 클릭 단계를 줄인다. |
| 이동 대상과 오류 | 브라우저 직접 연결용 오류 응답이 없었다. | HTTPS 쿠팡 도메인만 허용하며 상품 없음·잘못된 링크·조회 실패에는 UTF-8 텍스트로 503 안내를 반환한다. | 잘못된 주소로 이동하거나 예외 내용을 노출하지 않는다. |
| 캐시 | 직접 연결 응답의 캐시 설정이 없었다. | 직접 연결 응답에 `Cache-Control: no-store`를 지정한다. | 이전 상품으로 이동하는 응답을 재사용하지 않고 요청마다 선택한다. |
| 메뉴 설정 안내 | 챗봇 카드용 스킬 연결만 설명했다. | 실제 메뉴 URL, URL 연결 설정, 서버 배포 필요성 및 수수료 안내 위치를 문서화했다. | POST 스킬 주소와 브라우저 주소의 혼동을 방지한다. |

## 상세 변경

- 메뉴 URL: `https://kku-diet.onrender.com/go/coupang`.
- 선택한 상품의 저장된 파트너스 링크와 쿼리 문자열을 유지한다.
- 같은 상품이 연속 선택될 수 있다.
- 작업 전부터 있던 `RECOMMEND_INTRO` 관련 미커밋 변경은 보존하고 이번 직접 연결 변경과 구분한다.

## 영향 및 호환성

- DB 스키마, 저장된 상품 데이터, 환경변수, 인증 설정 변경 없음.
- 기존 `POST /api/recommend` 응답 계약 유지. 공개 GET 경로 하나 추가.
- 서버에 배포한 후 카카오 메뉴 연결을 URL 방식으로 설정해야 한다.
- 직접 이동은 기존 카드의 수수료 안내를 표시하지 않으므로 클릭 전 안내 위치는 별도 설정이 필요하다.

## 확인

- Flask 테스트 클라이언트와 모의 상품 조회로 서로 다른 두 요청의 302 응답, 파트너스 URL 및 쿼리 보존, `no-store` 확인.
- 상품 없음·잘못된 링크 9가지와 DB 예외의 503 안내 응답 확인.
- 기존 상품 카드, 파트너스 안내, 기존 로컬 도입 문구 설정 및 `/health` 응답 유지 확인.
- 첫 검증에서는 PowerShell 표준입력의 한글 인코딩으로 테스트 문자열 비교가 실패하여 Unicode 이스케이프로 고친 뒤 모두 통과했다.
- 배포 전 운영 주소 GET 요청: 404 확인.
- `36f1fd7` 푸시 후 운영 주소가 302로 전환되는 것을 확인했다. 운영 DB에서 선택한 `link.coupang.com` 링크와 `Cache-Control: no-store` 응답을 확인했다.
- 추가 운영 요청의 이동 대상이 로컬 `ads.json`에 등록된 파트너스 링크와 일치하는 것을 확인했다. 쿠팡 외부 페이지까지 따라가지는 않았다.
- Render 관리 화면은 연결된 브라우저가 없어 확인하지 못했으며, 실제 운영 서버 응답으로 반영 여부를 검증했다.

# Codex · 2026-09-20 · 추천 카드 썸네일 누락 경고 수정

**주요 파일**: `app.py`, `README.md`

## 배경

카카오 챗봇 관리자센터의 ‘쿠팡핫딜추천’에서 `BasicCard`의 `thumbnail` 필드 누락 경고가 발생했다.
기존 코드는 상품 이미지가 없으면 `thumbnail`만 생략한 채 항상 `basicCard`를 반환했다.
로컬 `ads.json`의 상품 14개 모두 이미지가 비어 있어 이 경로로 응답했다.
[카카오 공식 응답 규격](https://kakaobusiness.gitbook.io/main/tool/chatbot/skill_guide/answer_json_format)에 따르면 `basicCard.thumbnail`은 필수이며, 이미지 없는 텍스트와 버튼은 `textCard`로 표현할 수 있다.

## 기존 → 변경 후

| 구분 | 기존 | 변경 후 | 변경 이유 |
|---|---|---|---|
| 이미지 없는 상품 | 썸네일 없는 `basicCard`를 반환했다. | 이미지 필드 누락·null·빈 문자열·공백이면 `textCard`로 반환한다. | 필수 필드 누락을 없애면서 상품 설명과 구매 버튼을 제공한다. |
| 이미지 있는 상품 | 이미지 URL을 그대로 썸네일에 넣었다. | URL 앞뒤 공백을 제거하고 썸네일을 포함한 `basicCard`로 반환한다. | 정상 상품의 이미지 표시와 클릭 링크를 유지한다. |
| 응답 문서 | 모든 추천 응답을 `basicCard`로 설명했다. | 이미지 유무에 따른 두 카드 형식과 썸네일 필수 조건을 설명한다. | 실제 응답 형식과 상품 이미지의 선택 입력 정책을 일치시킨다. |
| 기존 도입 문구 변경 반영 | 카드 앞 고정 안내와 `RECOMMEND_INTRO` 설명이 로컬 미커밋 상태였다. | 사용자 푸시 요청에 따라 기존 변경을 이번 커밋에 함께 포함한다. | 검증한 응답 구성과 배포할 코드의 구성을 일치시킨다. |

## 상세 변경

- `/api/recommend`의 카드 형식만 이미지 유무에 따라 선택한다.
- 상품 제목, 구매 버튼, 저장된 파트너스 링크, 설명의 230자 제한 및 파트너스 안내를 유지한다.
- 작업 전부터 있던 `RECOMMEND_INTRO` 및 README 환경변수 설명을 보존하고, 후속 푸시 요청에 따라 함께 커밋 대상으로 포함했다.

## 영향 및 호환성

- DB 스키마, 저장된 상품 데이터, 필수 환경변수 및 인증 설정 변경 없음. 데이터 마이그레이션 불필요.
- 함께 반영하는 기존 `RECOMMEND_INTRO`는 선택 환경변수다. 미설정 시 기본 안내를 보내고 빈 값이면 안내를 생략한다.
- `POST /api/recommend`의 버전과 응답 구조는 유지하되 이미지 없는 상품의 출력 키가 `basicCard`에서 `textCard`로 변경된다.
- 운영 반영에는 서버 배포가 필요하며, 실제 카카오 경고 해제 여부는 확인하지 않았다.

## 확인

- Flask 테스트 클라이언트와 모의 상품 조회로 상품 응답 28개 검증 통과: 이미지 필드 누락·null·빈 값·공백·정상 URL·앞뒤 공백 URL, 도입 문구 표시/생략, 긴 설명 2종, 로컬 상품 14개.
- 카드 형식, 썸네일, 구매 버튼과 링크, 파트너스 안내, 설명 길이 및 도입 문구 보존 확인.
- 상품 없음 안내와 `/health` 정상 응답 확인. 위 검증에서는 DB나 외부 네트워크에 접근하지 않았다.
- `.venv/Scripts/python.exe -m unittest discover -v`: 기존 테스트 3개 통과.
